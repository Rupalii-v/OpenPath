# Orbit OSS — Open-Source Contribution Finder

A dark, responsive full-stack website that helps first-time contributors discover open GitHub issues matched to their skills and get a contribution brief generated by Gemma.

## Stack

- **Frontend:** HTML, CSS, vanilla JavaScript (no npm / no build step)
- **Backend:** Python + FastAPI
- **Live issues:** GitHub Search Issues API (public endpoint; optional token raises rate limits)
- **AI mentor:** Gemma through [Ollama](https://ollama.com/) on your own machine

## Features

- Responsive dark UI with animated orbital visuals
- Skills, experience, time, and interest profile
- Live search for open GitHub issues with beginner-friendly labels
- Match scoring and plain-language match reasons (heuristics, not guarantees)
- “Why this fits” brief from local Gemma: fit, difficulty, next steps, and cautions
- Graceful demo preview if GitHub search or the backend is unavailable
- Health endpoint at `/api/health`

## Run on macOS / Linux

Use Python 3.10+.

```bash
cd orbit-oss-finder
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
uvicorn backend.main:app --reload --host 127.0.0.1 --port 8000
```

Open **http://127.0.0.1:8000**. No npm install is needed.

### Connect Gemma (local, open-weight)

1. Install Ollama from https://ollama.com/download.
2. In Terminal, pull a Gemma model supported by your installed Ollama version. Example:

   ```bash
   ollama pull gemma3:4b
   ```

3. Ensure Ollama is running, then check `http://127.0.0.1:8000/api/health`.
4. If you pulled a different Gemma model, update `GEMMA_MODEL` in `.env` and restart FastAPI.
5. Click **Why this fits** on an issue. The backend sends the issue context and your profile to the local Ollama endpoint.

The model runs locally on your machine; the site does not need a paid model API key. GitHub issue search still requires internet access.

### GitHub API rate limits (optional)

Unauthenticated GitHub search has a low rate limit. Create a GitHub personal access token with no extra scopes needed for public repository reads, then set `GITHUB_TOKEN=...` in `.env`. Keep `.env` private; never commit the token. Restart the server after changing it.

## API

- `GET /api/health` — confirms API is running and reports whether a GitHub token is configured (never returns the token).
- `POST /api/search` — body: `{"skills":["Python"],"level":"beginner","time":"1-2 hours","interest":""}`. Returns live GitHub issues where possible, otherwise demo preview results.
- `POST /api/explain` — body contains `issue` and `profile`. Calls Gemma via Ollama and returns structured contribution guidance. Returns HTTP 503 if Ollama is not reachable.

## Important honesty / safety notes

- A match score is a heuristic, not an AI probability or a guarantee of acceptance.
- Labels and issue state can change. Always open the original issue, check recent comments, verify it is not already assigned/claimed, and read the repository's contribution guide before working.
- The demo cards are clearly labelled as preview data and are not proof that those exact issues remain available.
- This project is a starter application; before public deployment, add stricter request validation, API caching/rate limiting, logging, and production server configuration.
